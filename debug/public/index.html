Choose a device

Proposes a configuration with no device named: a name and the line settings, starting at 9600 baud. Change what your device needs and press Connect: the browser's port picker opens with no filter, so every port this browser offers is in it, USB adapters and built-in ports alike. Pick the one your device is on.

The configuration takes its identity from the port you chose — its USB vendor and product IDs, or the fact that it has none — and remembers it, so this visit and every later one connect without asking again. Other tabs that set the same name up without a device follow it.

Closing the picker without choosing sets nothing up.

Worker URL

The address of serial-broker.worker.js that your application loads. Tabs only find each other through the same worker, so enter exactly the URL your application uses. With any other URL this page starts a worker of its own and shows none of your tabs.

Changes take effect with Apply and reload. Copy link puts these settings into the page address, so the page opens elsewhere with the same settings.

Transport

How this page talks to the tabs of your application.

auto
A SharedWorker; a BroadcastChannel where the browser has no SharedWorker, refuses to create one, cannot load the worker script, or finds a worker of another protocol version. The default.
SharedWorker
Always the worker. If it cannot be used, you get an error instead of a fallback, which makes a worker script that is not served visible.
BroadcastChannel
Always the channel, as if there were no SharedWorker.

Use what your application uses: tabs on a SharedWorker and tabs on a BroadcastChannel do not hear each other.

Log payload bytes

Adds the bytes of every transfer to this page's log, as hex, in debug records. Off by default, because serial traffic can carry card numbers and PINs. Byte counts are logged either way.

It affects this page only. Transfers are logged by the tab that holds the port, so bytes appear here while this page holds it.

Browser

What serial-broker needs from this browser. A secure context is a page served over HTTPS or from localhost. Web Serial opens the ports. Web Locks make sure exactly one tab holds each port.

A red dot means serial-broker cannot run in this browser.

Message bus

How the tabs of this origin talk to each other. A SharedWorker is used where possible, a BroadcastChannel where there is none or its worker cannot be used. One of the two is enough, so a single missing one is only a warning.

A worker that stops answering is replaced: every tab reports BROKER_UNAVAILABLE once and carries on with a new one.

This page

This page's identity on the message bus, which the tables of tabs show in short form, and the bus it uses. A page joins the bus when it connects to its first configuration.

Protocol version

The version of the messages tabs exchange. Updates that change those messages raise it.

Tabs on different versions cannot share the device: each of them tries to hold it. They report PROTOCOL_VERSION_MISMATCH when they notice each other, and this page only lists the tabs on its own version. After such an update, reload every tab.

Port locks

The Web Locks that decide which tab holds each port, by configuration name. held: a tab holds the port. waiting: tabs lined up to take over when it goes away. A lock of another protocol version is marked with it.

The browser names tabs differently from the rest of this page, so the holder is not named here; a configuration's Overview shows it.

Granted ports

Serial ports this browser already allows this site to use, by USB vendor and product ID. A configuration connects to a matching port without asking. Disconnect… with Forget the device ticked removes a port from this list.

Status

Not running
Remembered from an earlier visit, but no tab uses it.
Idle
Set up, not trying to open the port yet.
Queued for a place
As many tabs as the tab limit allows use the configuration already. The tab receives nothing, and what it sends waits, until one of them disconnects, closes or crashes.
Waiting for device
No port this browser allows matches the device. Choose it once with Choose device….
Opening port
The tab that holds the port is opening it.
Port open
Data can be sent and is received, from every tab that uses the configuration.
Reconnecting
The connection was lost and is being restored.
Failed
Reconnecting gave up after the maximum number of attempts. It starts again when the device is plugged back in. A tab that withdrew over a different tab limit shows it too.
Released
A tab stopped using the configuration. Seen in the traffic.

Overview lists every tab that uses the configuration. holds the port is the tab that has the device open; a waiting tab uses it through that tab and takes over if it goes away; a queued tab waits for a place; a tab that withdrew takes no part until its tab limit matches.

Actions

Connect
Sets the configuration up in this page, with the settings shown, so you can send from here. If no tab uses it yet, this page opens the port; if the tab limit is reached, this page is queued for a place.
Choose device…
Shows the browser's port picker, in any tab using the configuration that is not queued; the tab holding the port opens the port chosen, and the browser remembers the choice.
Choose a different device…
For a configuration that took its device from the picker: shows every port again, and the port you choose becomes the device in every tab and in what is remembered. The tab holding the port closes the old device and opens the new one.
Edit settings…
Changes the settings this page uses: saving connects this page with the new ones, disconnecting first if it is connected. Other tabs keep theirs.
Disconnect…
Stops using the configuration in this page, and asks what else should go. Other tabs carry on; if this page held the port, another tab takes it over. On its own it forgets nothing: the configuration stays in the list, with Connect to start it here again, because this browser goes on remembering it and keeps its permission for the device — a disconnect is not a deletion. It is offered for a configuration this page is not using too, because what the dialog asks about is what the browser keeps, not what this page does.
Forget the configuration
Ticked in that dialog: removes the configuration this browser remembers under the name, so it is gone after a reload and your application's restore() no longer brings it back. It is one entry for the whole site, so it is removed only once no other page runs the configuration with remember, your application's included. The permission for the device is kept.
Forget the device
Ticked in that dialog: revokes this browser's permission for the device, so the next connection asks for the port again. With both ticked, nothing about the configuration is left in this browser.

Sending

text
Sends what you type as UTF-8, followed by the line ending chosen under Append.
hex bytes
Sends exactly the bytes you type, such as 02 FF 03, 02ff03 or 0x02,0xff. Nothing is appended.
Append
The line ending many text devices expect after a command.

The bytes reach the device through whichever tab holds the port. While this page is queued for a place, they wait.

Traffic

What crosses the bus for this configuration while this page is open, from every tab: data received, data sent and which tab sent it, status changes, errors, and which tab holds the port. The last 500 entries are kept.

Receiving

A device often sends an answer in pieces: an echo returns every byte on its own. The tab holding the port collects what arrives until the line has been quiet for the quiet time, and delivers it as one piece — 1234\r\n instead of six. 0 delivers every piece as it is read. The longest wait bounds a line that never goes quiet.

Device

Which device the configuration connects to. Automatic takes it from the port you choose in the browser's picker once the configuration waits for a device, and remembers it. Or name it: choose a common adapter to fill in its USB IDs, or enter the vendor ID and product ID the device reports, such as 0x1a86. The IDs name a kind of device, not a particular one.

For a port with no USB identity, such as a built-in RS-232 port, a Bluetooth serial port or a virtual COM port, choose Port without USB identity: the configuration then accepts only such ports. Any port accepts whatever port this browser allows.

Line settings

Baud rate, data bits, stop bits and parity must match the device exactly; its manual gives them. A mismatch does not fail, it produces garbage.

Flow control
hardware uses RTS/CTS. Only if the device and cable support it: otherwise every write waits and times out.
Buffer size
The read buffer the browser allocates. Raise it only for a device that sends large bursts.

Reconnecting

When the connection is lost, the tab holding the port tries again: at once, then after the first retry delay, each wait multiplied by the backoff factor up to the max retry delay. Each wait falls at random between the jitter fraction of it and all of it, so devices that failed together do not retry in step. When the browser reports the device plugged back in, it tries at once.

Max attempts
Attempts before the status becomes Failed. Infinity never gives up.
Stable after
How long a connection must hold before the attempt count starts over.

Timeouts and writes

Open timeout
How long opening or closing the port may take. A driver that hangs counts as a failed attempt.
Write timeout
How long a send may take, including waiting for a connection.
Write chunk
Large sends are handed to the device in pieces of at most this size. Lower it for a device that loses the end of large writes.

Text and memory

Text encoding
How received bytes are decoded into text.
Decode text
Adds the decoded text to received data, so traffic shows characters rather than only bytes.
Remember across reloads
Stores the configuration in this browser, so it can be set up again after a reload. The browser keeps the device permission either way.

Tab limit

At most this many tabs use the configuration at the same time, the tab that holds the port included. 1 gives one tab the device to itself. Leave it blank, or enter Infinity, for no limit.

Further tabs wait with the status Queued for a place: they receive nothing, and what they send waits. When a tab disconnects, closes or crashes, the tab that has waited longest moves up.

Every tab must use the same limit. A tab with a different one than the tab holding the port reports CONFIGURATION_CONFLICT and shows Failed.
